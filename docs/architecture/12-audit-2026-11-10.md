## Thesis

The stated goal is a swarm that needs no tending: a machine joins with near-zero
config, load spreads, slow and failing nodes are routed around, and any harness can use
it through a standard API.

**Verdict: the routing core is correct for nodes that fail fast and wrong for nodes that
fail slow.** Hard failures (refused connection, 5xx, capacity errors, mid-stream death)
are handled well and are well tested. A node that accepts a connection and then stalls
is not detected: the only deadline on the request path is a 120 s read timeout, load
balancing ignores latency, and a stalled node passes its health probe and returns to
full traffic. That is the largest gap against the goal.

Three further gaps sit around the core:

- **Trust.** The default swarm is an open LAN where any host can register itself as a
  peer and receive prompts, and admin routes can be reached from a web page in the
  user's browser.
- **Delivery.** Every release since v0.4.5.1 has a red release workflow, the macOS DMG
  is uploaded by hand, the Homebrew formula is two versions behind, and the Linux and
  Windows packages have never been installed by CI and are probably not relocatable.
- **Seamlessness off macOS.** Windows has no working background mode, the Linux unit is
  never enabled and stops at logout, no OS rejoins the mesh after an IP change, and the
  only Linux/Windows GUI cannot authenticate from another machine.

What held: package layering, the engine/adapter split, in-flight accounting on every
exit path, error envelopes per surface, dashboard XSS safety, config migration, and
version consistency across the workspace.
