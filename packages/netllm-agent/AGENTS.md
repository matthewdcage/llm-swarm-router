# netllm-agent

Parent: [../AGENTS.md](../AGENTS.md).

## Purpose

FastAPI agent daemon: OpenAI-compatible `/v1/*` (chat, models, embeddings), Anthropic `/v1/messages`, admin `/netllm/v1/*`, Prometheus `/metrics`, web dashboard `/ui/`.

## Ownership

Key modules: `app.py` (assembly only — see Local Contracts), `routes/` (one module per route
group: `root.py`, `telemetry.py`, `swarm.py`, `admin.py`, `inference.py`, plus `gates.py` and
`context.py`), `service/` (the `AgentService` mixin composition: `engine.py` is the
only failover loop, `surfaces/` the per-surface adapters, `accounting.py` the only accounting
writer), `admin.py`, `metrics.py`, `shard.py`, `request_plan.py`, `candidates.py`,
`taxonomy.py`, `errors.py`. Static UI: `static/` (HTML, JS, CSS, tokens).

## Local Contracts

- Default bind: `127.0.0.1:11400`; do not run menubar app and `./netllm serve` together (same port)
- **Route registration** (PROGRAM.md Phase 5b): `create_app` builds the service, lifespan, error handlers, `AccessGates` and a `RouteContext`, then calls every registrar in `routes.REGISTRARS` — it registers **no route itself** and is capped at 150 lines (`tests/test_route_auth_gates.py::test_create_app_stays_assembly_only`). A new route goes in the matching `routes/` module; a new *group* is a new module plus one line in `routes/__init__.py`
- **Auth gates are enumerated, not remembered**: routes call `ctx.gates.require_admin_access` / `require_read_access` / `require_inference_access` (`routes/gates.py`). The gate each route applies is pinned in `tests/contract/route-auth-gates.json`, derived by `scripts/generate-route-auth-gates.py` from the **pre-split** `app.py` and asserted against the running app; `ci.sh lint` runs `--check`. Adding a route means adding a row — an ungated route must be justified there (only `/`, `/health` and `/netllm/v1/heartbeat`, which does its own constant-time token compare, carry `null`)
- **`RequestPlan.exact_model_only`**: set when incoming `x-netllm-hops >= 1` (`surfaces/base.py`, `surfaces/messages.py`); threads through `policy.py` → `selection.py` → `engine.py` so the terminating peer serves the pinned model name only — no pool substitution on agent hops
- **Wire-payload adaptation is SDK-only** (`netllm-sdk-openai/payload.py`): agent/core must not duplicate provider stripping/normalization (no `provider_payload` in core)
- **`GET /netllm/v1/status`:** cache-fast by default (TTL-cached local scan, no forced health probe); `?scan=1` / `?probe=1` (local backends only) / `?probe_peers=1` (peer reachability via GET `/health`) for explicit Refresh/doctor — macOS Settings and dashboard **Refresh** pass all three; routine 2s polls use no flags
- Dashboard tokens: edit `apps/netllm-mac/design-tokens.json`, then run **both** `scripts/generate-dashboard-tokens.py` (→ `static/dashboard-tokens.css`) and `scripts/generate-swift-tokens.py` (→ `apps/netllm-mac/Sources/Config/DesignTokens.swift`); CI `--check`s both. The JSON is the only place a colour is written: the CSS emits `:root`, a `prefers-color-scheme` block and `:root[data-theme="light"|"dark"]` overrides (so the Preferences theme control can pin a mode), and the Swift emits appearance-aware `NSColor`s. Adding a token to the JSON needs no generator edit — both are data-driven
- **Static layout** (rewritten in the 11-page redesign): `dashboard.js` is the **core** — global `state`, `api()`, the shared DOM primitives every page is built from, config patching/save, the router and polling. `schema-form.js` is the generic schema-form engine. `pages/<key>.js` is one module per page, each calling `registerPage("<key>", fn)`. `bootstrap.js` is the entry point and loads last. Pages never call `fetch` directly and never hard-code a colour. The page roster is stated four times and all four must agree — `const PAGES` in `dashboard.js`, the `registerPage()` call in each module, and `data-page=` / `id="page-…"` in `index.html` — asserted by `tests/conformance/kit_config_surfaces.py`
- In-app update API: `GET /netllm/v1/update/check` (macOS menubar proxies this)
- **Admin routes** (`admin.py`): config save, doctor, version, logs, discover, peers-scan — allowed from **this host** (`local_admin_client_hosts()` in `netllm-core`) or `Authorization: Bearer <cluster_token>`; remote LAN clients get read-only status/models unless token is set
- **Doctor** (`doctor_payload`): open LAN without `cluster_token` is informational (`notes`), not an `issues` failure; secured pairing is optional via Settings / CLI
- **Web dashboard**: status/models load without admin; doctor/config failures degrade gracefully (warn banner, not fatal); cluster token label shows **open (trusted LAN)** when unset; `renderDiscoveryCredentialsSection` (in `dashboard.js`, rendered by the **Network** page's Security section) syncs per-URL API keys into `routing.backends` on Save (same rows as Routing → Backend overrides; macOS Settings mirrors this)
- **Untrusted strings**: model ids, peer hostnames, backend `base_url`s, `health.detail` and log lines are attacker-influenced — a LAN peer's `health.models` is republished through `/v1/models` (`swarm.py`). The dashboard therefore builds DOM with `textEl`/`el` only (**never `innerHTML`** — asserted by `tests/e2e/`), strips bidi/control characters in `sanitizeText`, routes every `href`/`src` through `safeHref` (http/https only), and — the one that bites — passes every value interpolated into a **copyable shell command** through `shellQuote` and every value in a **TOML/YAML/JSON snippet** through `configQuote`. Without those two, a hostile model id becomes extra commands on the user's clipboard
- **Models tab & pool pickers parity** (docs/models-ux-plan.md phase D — JS twin of `apps/netllm-mac/Sources/AppView/ModelsTabView.swift`/`CloudSettingsView.swift`, keep the three mirrors in sync): `renderModelsTab` groups `status.backends` by machine (local hostname, peer `hostname (agent_id)`, cloud `cloud_provider` as "<display name> (cloud)" — `state.config.cloud.providers[id].display_name` from `_cloud_provider_export`) with a search filter and per-row `routing.model_pools` badges (`poolInactiveReason` mirrors `ModelResolver._host_matches` in `pool.py` — keep dashboard, macOS, and core in sync) plus an add/remove/new-pool `<select>`, writing the same `configDraft.routing.model_pools` the Routing tab's generic dict-of-objects widget edits. `schemaListStringsRow` accepts `overrides.suggestions` (native `<datalist>`, assist-not-restrict) — wired for the Routing tab's model-pool `hosts`/`models` fields via `knownHostRefs()`/`knownModelIDs()`. Cloud tab's per-provider card gets a "Models" checklist (`renderCloudModelsSection`) fetching `GET /netllm/v1/cloud/providers/{id}/models` and toggling `cloud.providers.<id>.models` (empty = all, matching server materialization). Unlike the Swift build, this dashboard only re-renders the active page (not on every 2s status poll), so there's no view-model-vs-@State drift concern here. Post-redesign this all lives in `static/pages/models.js` (`renderModelsPage`, with the pool drill-in on `state.openPoolId`); the cloud checklist moved to `static/pages/cloud.js`.
- **Loop guard:** every forward to a `peer:` backend sets `x-netllm-local-only: 1` (`AgentService._peer_forward_headers`) so peers serve locally and never re-forward; routing-time peer reachability uses `GET {peer}/health` (not `/v1/models` on the peer); doctor and `?probe_peers=1` refresh peer cache the same way
- **`POST /v1/embeddings`** (`proxy_embeddings`): same selection/failover loop as chat incl. agent-hop to peers; Anthropic-format backends are excluded (no Anthropic embeddings standard); unknown model 404 lists embedding-capable models first
- **Capability gate:** chat/Messages requests against non-chat models (`netllm_core.capabilities`) return 400 with a `/v1/embeddings` hint — never burn the retry budget on encoders; 400 bodies quote the **requested** model name even when rewrites/scenarios change the effective id (F-57); `/v1/models` entries carry a `capability` field
- **Malformed JSON on inference routes:** `errors.parse_inference_json()` shapes invalid bodies as native OpenAI/Anthropic **400** envelopes (F-38); upstream 401/429 on OpenAI proxy routes remain **502** by design — see [03-request-lifecycle.md](../../docs/architecture/03-request-lifecycle.md#client-visible-http-status-on-v1-f-38-documented-2026-08-03)
- **Retry exclusion:** chat/stream/embeddings loops track per-request failed backend ids and pass `exclude_ids` so retries reach untried peers; upstream API keys resolve via `backend.resolve_api_key()` (env fallbacks incl. `LMSTUDIO_API_KEY`)
- **Peers-scan rows** are deduped by `agent_id` in discovery and flagged `self` in `peers_scan_payload` (dashboard labels "this machine", shows `also_reachable_at` for multi-homed hosts)
- **Failure accounting** goes through `AgentService._mark_backend_failure` (never `pool.mark_failure(backend)` directly in proxy loops): capacity errors exclude the backend for that request only and must not trip it offline; 400/404 on `peer:` hops do not increment the offline trip
- **`auto` strategy** resolves in `_select_backend_for_request` (shard context → batch_shard, else least_load); shardless batch_shard requests bump `_shardless_fallbacks` (in `/netllm/v1/status`) and log only at 1 then every 100th — never per-request
- **Config drift:** heartbeat/status carry `routing_strategy` + `version`; `peer_config_warnings()` feeds status `peer_warnings` and doctor `notes` on mismatch
- **Cloud materialization** (`AgentService._materialize_cloud_provider_backends`, called from every proxy entry point and `list_models_aggregated`): syncs enabled `[cloud.providers.*]` entries into keyed `cloud-<id>` pool rows, skips rebuilding an unchanged row (preserves probed health/model catalog across requests), and prunes rows for providers no longer enabled via `pool.prune_cloud_provider_rows` — `cloud.enabled=False` prunes all cloud rows including the legacy `anthropic-cloud`/`openai-cloud` env-key injects, which are now also tagged with `cloud_provider`
- **`admin.config_summary`/`apply_config_patch`** treat `cloud` like `routing.backends`: keys are write-only (`api_key_set: bool` in the read side; an omitted `api_key` in a patch preserves the stored one) — never round-trip a raw key over the admin API's GET path
- **Dashboard Save is section-scoped:** `buildConfigPatch()` in `static/dashboard.js` POSTs only sections whose wire shape differs from the last-saved config; `config_guards.apply_config_guards(..., patch=...)` runs cloud credential verification only when `cloud` is in that patch (Network-only saves no longer re-warn about unverified providers)
- **Drain** (`POST /netllm/v1/admin/drain {"draining": bool}`, admin-gated): toggles `AgentService.draining`, a runtime-only flag (never persisted to config.toml, resets to `False` on the next process start) surfaced in `status_payload()` — which `gossip_loop` sends verbatim as the heartbeat body, so every peer's `handle_heartbeat` picks it up and `SwarmRegistry.peer_agent_backends()` omits a draining peer entirely from routing candidates. Nothing here cancels requests already in flight on the draining agent — only *future* selection is affected, everywhere.
- **`agent.max_concurrency`**: self-declared per-machine cap, also carried in `status_payload()`/heartbeat; a peer's value lands on its `Backend.max_concurrency` in `peer_agent_backends()` (see `netllm-core/AGENTS.md`). Absent-tolerant both ways — an older peer's heartbeat omitting `max_concurrency`/`draining` reads as `0`/`False`.
- **Peer provenance and reach** (UI-4a): `status_payload()`/heartbeat also carry `providers` (`[{id, provider, model_count}]`, local rows only, capped at `MAX_PEER_PROVIDERS`, **never model names** — the body is gossiped to every peer every `heartbeat_interval_s`) and `also_reachable_at` (alternate LAN URLs, wildcard binds only). `PeerRecord.discovered_via` (`mdns`/`subnet_scan`/`static`/`heartbeat`/`join`) is *receiver-side* and deliberately **not** in the body — the sender cannot know how it was found. `SwarmRegistry.register_peer` carries the first specific answer forward across re-registration and remembers it per-URL beyond `prune_stale`, otherwise every peer relabels itself `heartbeat` one interval after discovery. Absent-tolerant both ways, same convention as `max_concurrency`/`draining`: an older peer omits both keys and reads as `[]`/`[]`; wire lists go through `normalize_peer_providers`/`normalize_peer_urls`, never `PeerRecord(**payload)`. Tests: `tests/test_peer_heartbeat_enrichment.py`.
- **Classified addresses** (UI-4a follow-up): `status_payload()`/heartbeat also carry `reachable_at` — `[{url, kind, interface}]` from `StatusMixin.own_reachable_endpoints()`, ordered most-useful-first (`netllm_discovery.lan.ADDRESS_KINDS`: `lan`, `vpn`, `container`, `link_local`, `loopback`) and **including** the advertised `listen_url` as its first entry. A wildcard bind answers on every local IPv4 and on a Docker host most of those are bridge gateways; listing them flat put five `172.x.0.1` lines above the only address a LAN peer can dial. `also_reachable_at` is derived from the same call (never computed separately, so the two cannot disagree about order) and stays a flat `list[str]`, complete on its own — an older client sees exactly what it saw before, better ordered. Treat `reachable_at` as a **classification lookup keyed on url**, not a replacement: this agent also observes peer addresses the peer never advertised, and those stay in the flat list unclassified. Absent = "unclassified", never "no alternates"; wire data goes through `normalize_peer_endpoints`, and an unrecognised `kind` is printed verbatim (a newer agent may know one this build does not). Classification lives agent-side because only the host can see its own interface names — `10.0.0.29` and `172.17.0.1` are both RFC1918, so no client can re-derive it. Tests: `tests/test_lan.py`, `tests/test_peer_heartbeat_enrichment.py`.
- **Wall-clock siblings** (UI-3): anything the UI renders as an age carries epoch seconds from the server — `BackendHealth.last_check_epoch_s` (`0.0` = never probed) alongside the monotonic `last_check`, which keeps its meaning because `pool._freshness_s` does the health-cache arithmetic with it; and `status.discovery.{last_scan_at, last_peer_scan_at}` (`null` = not run in this process), stamped by `scan_local_providers` / `subnet_scan_agents` **themselves**, never by the admin route that happened to trigger them. Tests: `tests/test_wall_clock_timestamps.py`.
- **`GET /netllm/v1/cloud/providers`** (`admin.cloud_provider_registry_payload`): single source of truth for cloud provider display metadata (id/display_name/notes/regions/auth_modes/default_api_format/api_key_env), consumed by the macOS app (`AgentAPI.cloudProviderRegistry`) so Swift never hand-mirrors registry text — see the "Schema triple-mirror drift" note in [docs/cloud-providers-plan.md](../../docs/cloud-providers-plan.md). Adding/editing a provider in `netllm_core.cloud_providers.CLOUD_PROVIDERS` is enough; no client-side text needs updating.
- **`GET /netllm/v1/harnesses`** (`admin.harness_registry_payload`, docs/cli-source-routing-plan.md Phase 4c/4d): known-harness registry (`netllm_core.known_harnesses.KNOWN_HARNESSES`) merged with configured `routing.sources` state and live PATH detection (`netllm_core.harness_detection.detect`, `shutil.which`-only, ~5min cache). `detected` never influences `enabled` — a source can be legitimately enabled here while its CLI lives only on a swarm peer; only a user action (dashboard toggle, `netllm sources toggle`, macOS "Add & enable") changes `enabled`. Additive endpoint — does not change `config_summary`/`status_payload` shapes, so an older dashboard/macOS build keeps working against an upgraded agent unmodified.
- **`GET /netllm/v1/cloud/providers/{id}/models`** (`AgentService.cloud_provider_models_probe`): full model catalog for one provider — live probe of the provider's models API with the configured key (OpenAI-style `GET /models`, or `x-api-key` + `/v1/models` for Anthropic-only endpoints), falling back to the registry's `static_models` (source `"static"`, status `no_api_key`/`static_catalog`/probe error). Deliberately ignores the `cloud.providers.<id>.models` allowlist: a materialized backend's `health.models` IS the allowlist once set, so the allowlist-editing UI (macOS Cloud tab checklist) needs this endpoint to show what *could* be enabled. Tests: `tests/test_admin_cloud.py`.
- **`GET /netllm/v1/config/schema`** (`netllm_core.config_schema.config_schema_document`, also reachable offline via `netllm config schema`): form *shape* (widget/type/options/write_only/read_only/item_schema) for the 6 editable config sections — companion to `admin.config_summary` (values). Adding a pydantic field to `NetllmConfig` needs a `json_schema_extra` hint only for non-default widget/secrecy behavior (see `tests/test_config_schema.py`'s drift check); the field then appears in the dashboard's `renderSchemaForm`-driven tabs and (for `ui`/`discovery`/`swarm`, and `routing.model_pools`) the macOS app for free. See [docs/config-schema-rewrite-plan.md](../../docs/config-schema-rewrite-plan.md).
- Depends on all other workspace packages except `netllm-cli`
- **Telemetry** (`telemetry.py`, `GET /netllm/v1/telemetry`): unified router + optional oMLX proxy; `watch=1` enables lazy oMLX `/admin/api/stats` + `/admin/api/activity` probes (refcounted subscribers); router session/alltime counters persist to `~/.config/netllm/stats.json`; `router.routed_requests`, `router.backends` (health + in_flight), and optional `history.router_rps`; optional `psutil` host block on Linux when installed
- **Home page** (`static/pages/overview.js`, page key **`overview`** — the label is "Home", the key is unchanged and pinned four ways by `tests/conformance/kit_config_surfaces.py`): the former Status and Serving tabs merged. Opens with a **masthead** (`ovRenderMasthead`) carrying the brand mark, the product name as the page's only `h1`, version + update action (which links to the Preferences update card rather than forking it), serving status, the node facts (host/role/listen/uptime/backends/peers), and the two copyable strings — `clientEndpointUrl()` and `swarmJoinCommand()`, both built in `dashboard.js` so the sidebar card and the Network join sheet resolve them identically. The join command never interpolates the cluster token and quotes every value (`shellQuote`); `tests/e2e/test_dashboard_masthead.py` pins that. **Metrics polling:** `startMetricsPolling()` (5s) runs on Home, Peers, Backends, Models, and Cloud — each tick fetches `/netllm/v1/status?watch=1` plus `/netllm/v1/telemetry?watch=1` and re-renders. Mesh share, the **Traffic by backend** table, and Peers/Models/Backends routed columns prefer `router.windows.by_backend` / `by_model` (default 5 min) with avg prefill/generation tok/s; cumulative `routed_requests` remains labelled since start. Shared helpers live in `dashboard.js` (`telemetryWindowCounts`, `telemetryWindowRow`, `telemetryBackendLatency`, `telemetryRoutedShare`). Router session/all-time tokens and requests always shown; oMLX live/session blocks when `omlx.available`; merges status `source_requests` and `scenario_requests`, telemetry `routed_requests` / `capacity_rejections`, active model + `routing_strategy`. **Caveat**: `avg_prefill_tps` / `avg_generation_tps` are measured only on streaming requests with TTFT; non-streaming traffic leaves them null — see `docs/telemetry-api.md` UI-1/UI-2

## Extension contract

- **Owns:** the API **surfaces** — `Surface` and `SURFACE_SPECS`
  (`taxonomy.py`), the `SurfaceAdapter` protocol and its implementations
  (`service/surfaces/`) — and the HTTP route manifest
  `tests/contract/routes.json`, generated by
  `scripts/generate-routes-json.py` as an **exact set**.
- **Serves:** every other package's registry to clients that cannot import
  Python — `admin.cloud_provider_registry_payload`,
  `admin.local_provider_registry_payload`, `admin.harness_registry_payload`,
  and `config_schema_document()` (which also carries `CONTROLS`). Serving the
  facts is what lets the JS and Swift copies be degraded-mode fallbacks
  rather than sources of truth.
- **Consumes only** for provider, config-section and harness facts: those are
  `netllm-core`'s. A payload builder here reads a spec; it never restates one.
- **No new mirrors:** never add a provider, surface or harness id literal
  outside its registry, and never add a `Surface`-keyed branch outside
  `service/surfaces/`. `scripts/check-engine-erosion.py --seams` fails on the
  second, against `tests/conformance/ledgers/surface-seams.toml`, which is
  **empty** — any entry is a regression that has to be argued in writing.
- **Known thin spot:** Axis C has no registry-parameterized kit. The eleven
  adapter contract tests parameterize over a hand-written `ADAPTERS` tuple in
  `tests/contract/test_surface_adapters.py`, so a new adapter that is not
  added there silently skips all of them.
- **Adding a surface:** [docs/extending/03-api-surface.md](../../docs/extending/03-api-surface.md).
